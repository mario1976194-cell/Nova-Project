# Engine Overview

This project uses a custom voxel engine built for the original Nintendo 3DS and its PICA200 GPU. The engine combines procedural world generation, chunk-based world streaming, a custom renderer, on-device audio decoding, versioned persistence, and performance instrumentation.

## Core Systems

### Rendering

The renderer is a dedicated module with a custom voxel mesher and a chunk-mesh pool using double-buffered slots. Its rendering features include:

- Per-face geometry culling for opaque blocks and plant geometry.
- Per-vertex ambient occlusion (AO).
- Distance fog and a day/night ambient-light tint cycle (240 seconds).
- Clip-volume triangle rescue for geometry near clipping boundaries.
- A per-chunk remesh queue, including remeshing triggered by world edits.
- A single-pass entity renderer with per-face UV islands.
- A 3-skin, 64×256 mob texture atlas and a separate UI atlas.
- A splash screen and gameplay crosshair.

### World Streaming and Chunk Management

- World dimensions: **16,000 × 16,000 × 256** blocks.
- Chunk cache: **7×7** chunks.
- Runtime render distance: adjustable from **3×3 to 7×7** through the settings menu.
- Background worker for world generation and meshing, with validated job handoff.
- Persistent world-edit overlay supporting **4,096 edits**.

The cache radius increased from 2 (5×5) in v1.0 to 3 (7×7) in v1.1. Render distance is now configurable at runtime rather than fixed.

### Procedural Generation

World generation is seeded and deterministic for a given 32-bit seed. A random seed is selected at launch. Terrain, biome placement, lakes, and trees are derived from the seed.

Generation includes:

- Perlin-based terrain, using moisture and temperature fields for biome selection.
- Five biomes: Plains, Forest, Desert, Snow Taiga, and Mountain.
- Biome-specific surfaces and vegetation density, including sand, snow, snow dirt, ice, and flowers.
- A snow line, lakes with sand shores, and trees with biome-dependent density.
- Continuous mountain terrain spanning approximately 60–160 blocks in height, with climbable slopes.

### Entity Rendering

Entities use a dedicated renderer with per-face UV islands. Mob textures are organized in a 64×256 atlas containing three skins. Entity rendering is separate from the terrain and UI atlas paths.

### Audio

The audio system is implemented in `music.c` and supports on-console decoding of:

- MP3 through `minimp3`.

Audio processing includes mono downmixing and decimation/resampling to fit within an **8 MB linear-memory budget**. The system also provides volume control, a status line, and a shuffled playlist that selects another track from `./music`.

### Persistence and Settings

The save format advanced from v2 in v1.0 to v12 in v1.1. Save handling includes:

- CRC32 integrity checks.
- Slot-map permutation validation.
- Value clamping during load.
- Atomic replacement through a temporary file.
- Version history and rejection of worlds generated by an incompatible generator.
- A `.bss` save buffer, replacing the 436 KB stack compound literal used in v1.0.

Runtime settings are persisted in `settings.cfg`.

### Memory, Performance, and Instrumentation

The engine includes a custom linear-heap allocator with accounting in `memmeter.c`, plus performance instrumentation in `metrics.c`.

The on-device metrics overlay can report:

- FPS and frame time.
- CPU and GPU metrics.
- Heap and linear-memory usage.
- Chunk and mesh counters.

The overlay is displayed on the top screen, and its visibility/settings toggles persist. Additional performance measures include a throttled bottom-screen GUI and a loading bar driven by music-decoding progress.

The project is developed with a **30 FPS budget** in mind for original 3DS hardware; this describes the performance target, not a guarantee that every scene maintains that rate.

## Tooling and Validation

- A host-side test harness expanded from **15 to 43 checks**.
- Test coverage includes terrain, lakes and biomes, save round-trips, tamper rejection, ARM stack-frame guarding, entity models, and stack depth.
- A Python asset pipeline compiles terrain, UI, mob, and splash atlases into `.t3s` and `.t3x` assets.
- The binary size increased from **445 KB to 1.15 MB** between v1.0 and v1.1.

## Engine Changes: v1.0 → v1.1

| Area | v1.0 | v1.1 |
|---|---|---|
| World dimensions | 1,024-wide, 64-block-high world | 16,000-wide, 256-block-high world |
| Chunk cache | 5×5 | 7×7 |
| Render distance | Fixed 3×3 | Runtime-adjustable 3×3–7×7 |
| Renderer | Earlier rendering implementation | Dedicated renderer module, chunk mesh pool, double buffering, AO, edit-triggered remeshing, and entity rendering |
| World generation | Earlier terrain generation | Seeded Perlin terrain, five biomes, lakes, trees, and taller climbable mountains |
| Audio | Not present in the v1.0 | MP3 playback and shuffled playlist |
| Save format | v2 | v12 with integrity checks and atomic replacement |
| Test harness | 15 checks | 43 checks |
| Binary size | 445 KB | 1.15 MB |
